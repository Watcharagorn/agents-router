# Read access command safety

Accessed 2026-10-18.

- [Codex command checks](https://github.com/openai/codex/blob/rust-v0.98.0/codex-rs/core/src/command_safety/is_safe_command.rs), also available at the [newer location](https://github.com/openai/codex/blob/rust-v0.101.0/codex-rs/shell-command/src/command_safety/is_safe_command.rs). The requested `main` paths returned 404, so these tagged sources were inspected. Codex checks known commands and their options: `find` actions that execute or write, ripgrep preprocessors/hostname helpers/decompressors, and Git output, textconv, external diff, pager and config overrides need approval. We adopt that approach with a smaller option allowlist; unknown options go to review. [Codex's license](https://github.com/openai/codex/blob/rust-v0.101.0/LICENSE) and this repository's license are Apache-2.0. No Rust code was copied.
- [Claude Code permissions](https://code.claude.com/docs/en/permissions#bash). `:*` is equivalent to a trailing space and wildcard. `Bash(git diff:*)` therefore covers options such as `--output=FILE`; it cannot express option exclusions. Claude also has built-in read command approvals. Read workers keep their shell prefixes and get a separate command-validation hook.
- [Claude Code hooks: PreToolUse decision control](https://code.claude.com/docs/en/hooks#pretooluse-decision-control), accessed 2026-10-18. A synchronous `PreToolUse` hook returning `hookSpecificOutput.permissionDecision: "deny"` prevents the call; allow rules cannot override that denial. Deny also wins over another hook's allow decision. Returning no decision leaves the normal permission flow in charge. Hooks run in `-p` mode, and `dontAsk` is a documented hook-input permission mode: the guard needs no interactive permission request. These docs establish the headless behavior; this change's tests use fake workers, with no live model calls.
- [Anthropic's Bash command validator example](https://github.com/anthropics/claude-code/blob/main/examples/hooks/bash_command_validator_example.py), accessed 2026-10-18. The standard-library Python script reads hook JSON on stdin, checks `tool_input.command`, and blocks offending commands with exit code 2. We use the documented JSON deny response and our own shared command parser. The repository's [license](https://github.com/anthropics/claude-code/blob/main/LICENSE.md) was checked; no example code was copied.
- The [fd manual](https://github.com/sharkdp/fd/blob/master/doc/fd.1) documents `-l`/`--list-details` as an alias for external execution; these options also go to review. [Get-Command](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/get-command?view=powershell-7.5) can import modules when asked for a command by name, so it is no longer auto-approved. Bare operands of `hostname` and `date` can change system state and are restricted too.

Antigravity read jobs send recursive, wildcard and pipeline content reads to review because checking only literal arguments cannot exclude secrets reached indirectly. Interpreter code also goes to review regardless of sandboxing. Windows secret checks normalize stream suffixes, trailing dots/spaces and case, and reject ambiguous DOS short names.

Claude read jobs add a synchronous `Bash|PowerShell` hook to the existing per-job `--settings` file, alongside user hooks and the inbox `PostToolUse` hook. It invokes `claude_read_hook.py` with `sys.executable -I` through the existing cross-platform hook command builder. The script bootstraps its package path, reuses `agy_review.commands.read_only` and `agy_review.paths.check`, denies unrecognised commands/options and named secret paths, and stays silent for safe commands. Bash uses forward-slash paths: backslash escapes are rejected on Windows too, so Git Bash cannot turn a supposed operand into an option. PowerShell keeps native Windows paths. Invalid payloads or validation errors deny; `onFailure: "block"` covers hook startup errors and timeouts. Read launches refuse malformed hook settings or an overlay with `disableAllHooks` enabled. Edit and full jobs keep their existing settings and permissions.

The Git option allowlists already accept numeric log limits and ordinary read options. The parser accepts `git log --oneline -5`, `git diff HEAD~1`, `git diff main...HEAD`, `git show HEAD:path` and literal paths after `--`. HEAD ancestry is treated as a revision before `--`; a literal DOS-style filename after `--` still receives the path check. Output files, external diffs, textconv and config overrides remain excluded.

Claude keeps broad searches such as `rg pattern src`, as well as its native search tools. Its hook checks paths named in the command and their resolved link targets; it does not enumerate every file a recursive search might read. Antigravity's broader content-review rule remains separate. The hook is an option/path guard, not a filesystem sandbox; local executable configuration and repository configuration still matter.
